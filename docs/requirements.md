# 原始任务与范围

## 2026-10-10 六项能力增补

用户在审查后要求增加 Memory、Chat History、API Key、正文路径、push 前检查和 AI 语义判断，保留无侵入外接与固定内容代码强约束。实现范围为：指定导出来源提示并继续扫描内容；正文路径脱敏建议；显式多 tip/base 本机范围与覆盖报告；可选本机隐私分类模型；修复保护根目录与参数回显；可分发 Skill 包。仍不读取真实认证/运行目录，不自动修改、安装 hook、推送或调用云端服务。

验收必须区分接口和模型效果：语义接口、离线参数、失败路径与风险单调性可用替身验证；真实模型权重效果、precision/recall、客户端接入仍需另行实际验收。默认只做规则检查，不把未启用语义写成语义已通过。产品不保证宿主全部外发入口必经检查。

## 当前有效需求（2026-10-10 用户澄清）

用户希望它作为无侵入的外接 Skill 或 MCP，允许中途调用自己的规则代码，只读检查并给出建议。修改建议交给用户，由用户自行决定是否另行让 AI 调整目标项目。工具不自行修改、不执行建议、不阻断 Git 或 Claude 命令、不改变现有系统/项目/客户端配置。

因此下面附件提取的 hook 路线属于历史设计，已被此澄清替代。当前验收是：只读 CLI + Skill + 本地 stdio MCP；脱敏问题与可操作建议；技术失败明确标为未完成检查；文件、Git index/状态/配置保持不变；不自动登记或安装。旧 hook 安装入口停用，客户端样例只提供文件供用户自行选择接入。

用户最新的“调整”特指建议由用户拿去让 AI 修改，不意味着本工具应该在审查后继续自动执行修复。当前工具只提供审查接口，没有写入或修复接口。

## 历史请求与附件方案

2026-10-10 用户要求：在工作区新建项目，实现所附评估文中的 Agent 隐私守卫，并沿用通用 AGENTS 规则，保证项目可追踪管理。

来源为本次用户粘贴的评估文本。本文件提取功能需求；其中旧仓库扫描数字、工具版本、仓库公开状态属于附件作者的历史陈述，没有据此检查真实仓库或认定当前状态。

## 验收边界

原生 Windows 为本次主要运行平台；Git hook 使用 Git for Windows 的 shell 和 py -3。工具是本机控制层，可被有权修改配置的操作者绕过，不承诺服务端保护、读取侧保护或完整 shell 解释器覆盖。
